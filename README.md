# TiaPortalLab

Лаборатория опытно-экспериментальных технологических приложений на Siemens TIA Portal V19.

## Задание: Управление конвейером

## Цель

Учебная задача управления конвейером.

## Платформа

| Параметр | Значение |
| -------- | -------- |
| Среда разработки | Siemens TIA Portal V19 (STEP 7 + WinCC Basic) |
| Контроллер | SIMATIC S7-1200, рекомендуется CPU 1212C DC/DC/DC (`6ES7 212-1AG40-0XB0`) |
| Язык программирования | SCL (Structured Control Language, МЭК 61131-3) |
| Симуляция | S7-PLCSIM V19 (`C:\Program Files\Siemens\Automation\PLCSIM_V19`) |
| Имитация поля (датчики и механизмы) | Factory I/O — драйвер «Siemens S7-1200/1500» (S7/PUT-GET) или OPC UA |
| Панель оператора | HMI-панель в TIA Portal (WinCC Basic) |
| Что хранится в git | экспортированные исходники (`*.scl`, `*.db`), `PLCTags.xml`, документация |

Соглашения по стилю, архитектуре и инструментам — в `.clinerules/standarts.md`.

## Описание системы

Управление манипулятором, который перемещает груз с одной ленты на другую.

- Датчик поворота - пока манипулятор попорачивается вокруг своей вертикальной оси - датчик включен. Как только манипулятор стоит или завершил поворот - датчик перестает быть включенным.
- Датчик опускания/подъема - пока манипулятор опускает или поднимает захват внизу - датчик включен. Как только манипулятор стоит или завершил подъем/опускание - датчик перестает быть включенным.
- На ленте, где появляется груз установлен НЗ-оптический датчик, определяющий что груз есть для перемещения манипулятором.
- Команда поворота манипулятора относительно своей вертикально оси по часовой стрелке.
- Команда поворота манипулятора относительно своей вертикально оси против часовой стрелке.
- Команда опускания захвата с магнитом вниз до уровня конвейера, где появляется груз.
- Команда включить магнит и захватить груз, который находится внизу под опущенным захватом.

### Уровни сигналов датчиков (НЗ / NC)

Датчики нормально закрытые, поэтому в программе их сигнал **инвертируется** (слой `HardwareInput`):

| Состояние | Сигнал на входе ПЛК | «Коробка обнаружена» в логике |
| --------- | ------------------- | ----------------------------- |
| коробки нет | `1` (TRUE) | FALSE |
| коробка есть | `0` (FALSE) | TRUE |
| обрыв провода / нет питания | `0` (FALSE) | TRUE — неотличимо от коробки, учитывать при диагностике |

## Требования к программе на ПЛК

1. **Пуск**: при обнаружении коробки датчиком в начале ленты лента включается (`DO_ComMotor = 1`).
2. **Самоподхват**: после схода коробки с датчика начала лента продолжает работать.
3. **Останов**: при обнаружении коробки датчиком в конце ленты лента выключается (`DO_ComMotor = 0`). Останов выполняется по появлению коробки на датчике (передний фронт), чтобы коробка, остающаяся на датчике, не блокировала следующий пуск.
4. **Повторный пуск**: только при появлении следующей коробки на датчике начала.
5. **Безопасный старт**: при переходе ПЛК STOP→RUN лента не должна запускаться самопроизвольно.
6. **Структура**: OB1 (`ProgramCycle`) → `ConveyorMain` (оркестратор) → `HardwareInput` / `LogicDevice` / `HardwareOutput` / `HMIInterface`.

## Требования к интерфейсу оператора (ЧМИ)

1. Индикация работы двигателя конвейера одной лампочкой — «конвейер работает» (`HMI_LampWork` / `"Hmi_DB".LampWork`).
2. Лампы индикации сбоев, запретов, ошибок — красные (`HMI_LampFault` / `"Hmi_DB".LampFault`).
3. Лампы и кнопки панели **не занимают** физические выходы ПЛК: это поля DB или теги `HMI_*` без адреса.
4. Отдельная кнопка «Стоп» и аварийный останов — при появлении соответствующих требований в задании.

Поля global-DB `Hmi_DB` — единственный канал обмена с панелью; заполняет их блок `HMIInterface`:

| Поле | Тип | Смысл |
| ---- | --- | ----- |
| `"Hmi_DB".LampWork` | `Bool` | лампа «конвейер работает» |
| `"Hmi_DB".LampFault` | `Bool` | красная лампа сбоя / запрета / ошибки |

## Входы/выходы

Имена и адреса соответствуют `PLCTags.xml` (таблица `InOut`). Адреса действительны, если в конфигурации оборудования CPU имеет встроенные DI с `%I0.0…` и DQ с `%Q0.0…` (как у CPU 1212C).

### Входы

| Имя в TIA | Описание | Тип | Адрес |
| --------- | -------- | --- | ----- |
| `DI_SensorA` | НЗ-датчик в начале ленты | `Bool` | `%I0.0` |
| `DI_SensorB` | НЗ-датчик в конце ленты | `Bool` | `%I0.1` |

### Выходы

| Имя в TIA | Описание | Тип | Адрес |
| --------- | -------- | --- | ----- |
| `DO_ComMotor` | Команда «двигатель конвейера» | `Bool` | `%Q0.0` |
| `DO_LampWork` | Лампа «конвейер работает» (только если лампа физическая) | `Bool` | `%Q0.1` |

> Для панели оператора лампа должна быть отдельным тегом/полем DB (`"Hmi_DB".LampWork`), а не физическим выходом `%Q0.1`.

### Требования к оборудованию

1. ПЛК — SIMATIC S7-1200 (CPU 1212C DC/DC/DC, FW ≥ 4.4), питание 24 В DC.
2. Два индуктивных/оптических датчика с НЗ-выходом (тип NC, PNP) на `%I0.0` и `%I0.1`.
3. Реле/пускатель двигателя конвейера на `%Q0.0` (катушка 24 В DC, ток не выше допустимого для выхода CPU).
4. Лампа «работа» — на панели оператора; физическая лампа на `%Q0.1` — опционально.

## Развёртывание в TIA Portal V19

Репозиторий содержит **не проект, а экспортированные исходники**. Проект создаётся в TIA Portal и наполняется ими.

1. **Создать проект**: TIA Portal V19 → `Project → New…` → указать папку и имя `TiaPortalLab` → `Create`.
2. **Добавить контроллер**: `Devices & networks → Add new device → Controllers → SIMATIC S7-1200 → CPU 1212C DC/DC/DC → 6ES7 212-1AG40-0XB0 → OK`.
3. **Проверить адреса I/O**: в `Device view` выделить CPU → `Properties` → `PROFINET interface` (IP-адрес) и адреса встроенных DI/DQ. Они должны совпадать с `PLCTags.xml` (`%I0.0`, `%I0.1`, `%Q0.0`, `%Q0.1`).
4. **Импортировать теги**: `PLC_1 → PLC tags → Show all tags` → ПКМ → `Import…` → выбрать `PLCTags.xml` → `OK`.
5. **Импортировать блоки**: `PLC_1 → External source files` → `Add new external file` → выбрать `ConveyorObject\*.scl`, `ConveyorObject\Logic\*.scl`, `ConveyorObject\*.db`, `ProgramCycle.scl` → ПКМ по каждому файлу → `Generate blocks from source` → `OK`.
   Порядок важен: сначала FB (`HardwareInput`, `HardwareOutput`, `LogicDevice`, `HMIInterface`, `ConveyorMain`), затем global-DB (`Hmi_DB`), затем single-instance DB (`ConveyorMain_DB`), затем OB (`ProgramCycle`). Если блок ссылается на несуществующий тип — TIA выдаст «тип не найден».
6. **Проверить нумерацию OB**: `ProgramCycle` должен быть циклическим организационным блоком **OB1** (в свойствах блока — «Program cycle»). В проекте не должно остаться двух циклических OB.
7. **Скомпилировать**: ПКМ по `PLC_1` → `Compile → Software (rebuild all blocks)` (или `Ctrl+B`). Ожидается 0 ошибок.
8. **Загрузить/симулировать**: `Online → Start simulation` (при установленном PLCSIM V19) → `Download to device → Hardware and software`; либо загрузка в реальный CPU по PROFINET.

## Симуляция поля в Factory I/O

Датчики и механизмы имитируются в **Factory I/O**: среда пишет значения датчиков в ПЛК и читает команды на двигатель. Поэтому у всех тегов I/O в `PLCTags.xml` открыты права `hmiVisible`, `hmiAccessible`, `hmiWriteable` (`True`) — занижать их нельзя.

### Карта сигналов (совпадает с `PLCTags.xml`)

| Сигнал Factory I/O | Направление | Тег ПЛК | Адрес | Тип |
| ------------------ | ----------- | ------- | ----- | --- |
| НЗ-датчик «начало ленты» | Factory I/O → ПЛК | `DI_SensorA` | `%I0.0` | `Bool` |
| НЗ-датчик «конец ленты» | Factory I/O → ПЛК | `DI_SensorB` | `%I0.1` | `Bool` |
| Двигатель конвейера | ПЛК → Factory I/O | `DO_ComMotor` | `%Q0.0` | `Bool` |
| Лампа «работа» (если физическая) | ПЛК → Factory I/O | `DO_LampWork` | `%Q0.1` | `Bool` |

### Настройка

1. **Драйвер S7 (S7-1200/1500)**: в TIA у CPU включить `Properties → Protection & Security → Connection mechanisms → Permit access with PUT/GET communication from remote partner`; в Factory I/O сигналы привязываются к абсолютным адресам `I0.0`, `I0.1`, `Q0.0`, `Q0.1`.
2. **Драйвер OPC UA**: у CPU включить `OPC UA → Server` (FW ≥ 4.4), теги остаются с открытыми правами; в клиенте они доступны по именам.
3. **С PLCSIM V19**: сначала `Online → Start simulation`, затем подключение драйвера Factory I/O к виртуальному CPU.
4. НЗ-датчики: в Factory I/O используется **нормально замкнутый** контакт (значение `TRUE`, пока коробки нет), иначе логика будет инвертирована.

> Писать в `DI_*` может только Factory I/O, в `DO_*` — только программа. Двойная запись в один тег даёт «плавающие» ошибки.

## Отладка и симуляция

1. `Online → Go online`; открыть блок — включить `Monitoring on/off` (иконка «очки»): видны текущие значения в коде.
2. **Таблица наблюдения**: `PLC_1 → Watch tables → Add new watch table`; добавить `"DI_SensorA"`, `"DI_SensorB"`, `"DO_ComMotor"`, `"ConveyorMain_DB"`; нажать `Monitor all`.
3. **Modify now** — однократная запись значения (для тегов и полей DB). Названия кнопок зависят от версии/локализации TIA.
4. **Force** — принудительная запись: в TIA это force job, он переживает перезапуск мониторинга и снимается через `Force → Delete all force jobs` либо переводом CPU в STOP. Обязательно снимать после отладки — иначе поведение программы искажено.
5. **PLCSIM V19**: входы `%I` в реальном CPU перезаписываются образом входов, поэтому для эмуляции датчиков используйте SIM table в PLCSIM (или Force). Прямая запись в `%I` из таблицы наблюдения ожидаемого эффекта не даёт.
6. **Trace** (S7-1200 поддерживает трассировку) — для разбора редких событий и дребезга датчиков.

#### Циклограмма одного цикла (одна коробка)

```text
DI_SensorA       ‾‾‾‾‾\_________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
                       ↓         ↓
boxOnStart       ______/‾‾‾‾‾‾‾‾‾\___________________________________________
                        ↓
logic.ComRotate  _______/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\_________________
                         ↓                                 ↑↓
DO_ComMotor      ________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\________________
                         ↓                                 |↓
DO_LampWork      ________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\________________
                                                           |
DI_SensorB       ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\_________/‾‾‾‾‾‾‾‾‾
                                                          ↓|        ↓
boxOnEnd         _________________________________________/‾‾‾‾‾‾‾‾‾\________
```

Обозначения: `‾` / `_` — уровень сигнала (TRUE / FALSE); `/` и `\` — фронт сигнала, новый уровень начинается со следующего столбца; `↓` — стрелка реакции сверху вниз, `↑` — снизу вверх, стрелка всегда стоит на фронте сигнала-следствия; `|` — вертикальная причинно-следственная связь по столбцу сигнала. **Правило столбцов (универсальное, без привязки к именам):** `+1` столбец = следующий шаг обработки по цепочке «вход → логика → выход»; сигналы одного шага меняются в одном и том же столбце; проверка корректности схемы: столбец фронта-следствия = столбец фронта-причины + 1; все шаги выполняются в одном цикле сканирования (OB1), поэтому `1` столбец — условная единица времени, а не отдельный скан.

## Известные ограничения (на момент экспорта)

- Блоки хранятся как внешние источники: после правки `*.scl`/`*.db` их нужно заново генерировать в TIA (`Generate blocks from source`), иначе в проекте останется прежняя версия блока.
- Панель оператора (WinCC Basic) не создана: экраны, кнопки и привязки элементов к `"Hmi_DB"` выполняются в GUI TIA. В репозитории есть только global-DB панели и блок `HMIInterface`.
- Права `hmiVisible`/`hmiAccessible`/`hmiWriteable` у всех тегов I/O — `True`. Это сделано намеренно: теги читает и пишет Factory I/O (см. раздел «Симуляция поля в Factory I/O»). При этом писать в `DI_*` должна только Factory I/O, а в `DO_*` — только программа.
- Лампа «работа» дублируется: физический выход `%Q0.1` (`DO_LampWork`) и поле панели `"Hmi_DB".LampWork`. Если физической лампы нет, выход остаётся неиспользованным и в TIA его можно не подключать.
- Нет тегов аварии, кнопки «Стоп» и режимов (`HMI_LampFault`, `DI_EStop`, `HMI_CmdStart`, `HMI_CmdStop`): поле `"Hmi_DB".LampFault` есть, но источника сбоя в задании нет, поэтому лампа всегда погашена (`HMIInterface` получает `BeltFault := FALSE`).
- Нет контроля доезда коробки по таймауту: при обрыве датчика конца лента работает бесконечно.
- Останов выполняется по переднему фронту конечного датчика (`R_TRIG` в `LogicDevice`): коробка, оставшаяся на датчике, не блокирует пуск, но и нового фронта не даёт — если следующая коробка придёт при уже занятом конечном датчике, лента не остановится. Нужен контроль схода коробки (таймаут или второй датчик) — при появлении такого требования в задании.
- Нет блокировки пуска при занятом конечном датчике (если по технологии это требуется — уточнить в задании).
- Файл проекта `*.ap19` в git не хранится: конфигурация оборудования воспроизводится по разделу «Развёртывание».
